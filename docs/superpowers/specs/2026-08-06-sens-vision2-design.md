# Sens Vision 2.0 — дизайн-спек

Дата: 2026-08-06
Статус: одобрен пользователем, готов к планированию
Подход: A «документ визуального контекста» + интерактивный tool-loop

## 1. Контекст и цель

Sens даёт «чувства» текстовым LLM (потребитель — DeepSeek v4 Flash и аналогичные) через MCP. Текущий sight-пайплайн (L0–L5, `sidecars/sight-worker.py`) возвращает плоский дамп метрик: нет семантики графики, декоративный текст гибнет в OCR (круговая надпись → мусор вида `L4e4b'K8, WEb5+uN-20`), нет стиля/вайба, QA-эвристики дают ложные проблемы на намеренных стилях (брутализм → «uneven card heights»), нет интерактивности. Холодный старт 38 с.

Цель Vision 2.0: текстовая модель по артефактам Sens может
1. воспроизвести дизайн со скриншота или ссылки, включая моушен;
2. делать QA своего рендера, включая вайб/вкус, а не только геометрию;
3. точечно править детали («вот тут ошибка»);
4. понимать декоративную графику: dot/ASCII-паттерны, круговой/вертикальный текст, иллюстрации.

Фикстуры приёмки: `qa/incoming/2026-08-06T02-5*.png` (постер Summer Drive, Hyperstudio, Mono X7) + URL eathungrytiger.com, dope.security, caldera.xyz, chatgpt.com.

## 2. Ограничения (жёсткие)

- 100% бесплатно: никаких платных VLM API. Сеть — только явный скрипт скачивания моделей (и опциональный Eye с ключом пользователя — вне рамок этого изменения).
- Инференс строго CPU + системная RAM, видеокарта не трогается вовсе (не «fallback», а единственный путь). Пик памяти моделей ≤ ~2 ГБ RAM.
- Rust-брокер — единственный владелец воркеров и mutable-состояния; stdout `sens-mcp` чистый (протокол только), диагностика в stderr.
- Каждый результат — через общий request/result envelope с раздельным provenance: observed / measured / inferred.
- Переносимость: стек работает на машинах без GPU.

## 3. Выбор подхода

A + tool-loop: детерминированное ядро = источник истины для всего измеримого; малые локальные VLM = семантические подпрограммы (философия OmniParser «маленький парсер → большой LLM»); поверх — tool-loop потребительской модели (ViperGPT/SeeAct).

Отклонены: B «VLM-центричная» (галлюцинации малых VLM, потеря точности измерений — главного преимущества Sens); C «чистый tool-loop» (медленно, накопление ошибок, нет one-shot дампа для сценария «кинул скриншот — что не так?»).

Украдено из ресерча (2026-08-06): SoM-индексы (SeeAct/OmniParser); целые координаты 0–1000 текстом (Qwen2-VL/InternVL/OS-Atlas); caption по функции элемента (OmniParser V2); грубое→точное, фиксированный бюджет детализации (LLaVA-NeXT AnyRes/CogAgent); ASCII luminance-карта ~1–2k токенов (arXiv:2606.21470, 2603.14505); W3C DTCG design tokens как формат эстетики (свободные описатели без чисел → галлюцинации); моушен = CSS-парсинг + frame-diff→текстовые события; Design2Code: извлечённый текст+токены дополняют представление, идеал — DOM/HTML при наличии ссылки.

## 4. Архитектура

### 4.1 sight-worker — рефакторинг, не снос

Entrypoint `sidecars/sight-worker.py` сохраняется (брокер стартует по пути); логика выносится в пакет `sidecars/sight/`: `perception` (текущие L0–L5), `decorative` (детекторы), `tokens` (DTCG), `ascii_map`, `tree` (закоммиченная иерархия секций), `document` (сборщик), `capture` (url-capture).

Новое в ядре:
- DTCG-токены: палитра с ролями и покрытием, типографическая шкала (family/size/weight/tracking/case), ритм отступов, радиусы, тени, бордеры;
- SoM-нумерация всех элементов + целые нормализованные координаты 0–1000;
- детектор декоративного текста: круговой — центры OCR-боксов ложатся на окружность (RMS фитинга ниже порога); вертикальный — боксы h≫w в колонке;
- классификация графических регионов (фото/иллюстрация/паттерн/ascii-art/рендер): детерминированные признаки + VLM-caption;
- ASCII-карта яркости 96×48 (конфиг, default on);
- QA-рефрейм: эвристики пишут ФАКТЫ в секцию measurements (provenance=measured), не «issues».

### 4.2 vlm-worker — новый сайдкар

- **moondream2** GGUF Q4_K (~1.7 ГБ RAM), llama-cpp-python, `n_threads` = CPU, без CUDA. Роли: `vibe(screen)`, `transcribe(region)` (декоративный текст), `describe(region)`, `ask(region, question)`, `ground(query)`-fallback.
- **Florence-2-base** ONNX int8 (~0.3 ГБ), onnxruntime CPU (зависимость уже есть). Роли: описания регионов, dense captioning — быстрые пакетные вызовы.
- Тёплый старт при запуске брокера (асинхронно), выгрузка после idle (конфиг, default 10 мин).
- Протокол с брокером — тот же JSON stdin/stdout, что у остальных воркеров.

### 4.3 url-capture — модуль sight-worker, playwright опционален

Для URL: скриншот; извлечение DOM/CSS — шрифты (`document.fonts` + computed), computed styles ключевых узлов, `animation`/`transition`/`keyframes` (CSSOM + `getAnimations`); скролл-кадры → frame-diff → текстовые события моушена («элемент [id] сместился на 200px вправо за 0.4s, ease-out»). Playwright не установлен → операция возвращает понятную ошибку с инструкцией установки; тихой деградации нет.

### 4.4 Rust-слой — минимально

- `crates/sens-broker/src/sight.rs`: маршрутизация новых операций, жизненный цикл vlm-worker;
- `crates/sens-mcp`: новые инструменты `sens_zoom`, `sens_ask`, `sens_element`, `sens_motion`, `sens_capture`; `sens_see` возвращает документ; legacy-поля текущего дампа сохраняются под ключом `legacy` на один релиз для совместимости, затем удаляются.

Никакой логики зрения в Rust не переносится.

## 5. Документ визуального контекста

Канонический артефакт `sens_see`. Внутри — канонический JSON; модели рендерится компактный markdown. Бюджет ≤ 4k токенов на экран (включая ascii ~1.2k). Язык — русский с английскими техтерминами (конфиг `lang: ru|en`, default ru; DeepSeek силён в обоих, пользователю дебажить).

Секции с provenance:
- header (measured + inferred): размеры, тема, сцена, vibe-подпись [inferred, moondream];
- palette (measured): hex + роль + покрытие;
- typography (measured): шкала, семейства, веса, трекинг, case;
- grid/spacing (measured);
- elements (observed/measured): SoM-id, роль, текст, шрифт, бокс 0–1000;
- decorative (observed + inferred): круговой/вертикальный текст, направление чтения, транскрипция [inferred, moondream];
- graphics (measured-боксы + inferred-подписи): тип, caption [Florence/moondream], доминантные цвета;
- motion (measured, только для URL/кадров): CSS-события + frame-diff события;
- ascii (measured): карта яркости 96×48;
- measurements (measured): факты без оценок — число блоков, контрасты, разбросы выравнивания;
- semantics_status: какие inferred-секции доступны/недоступны.

## 6. Tool-слой (tool-loop)

- `sens_see(image|url, fast=false)` — документ; `fast=true` пропускает moondream (Florence + ядро), ~2–4 с;
- `sens_zoom(region | som_id)` — суб-документ региона с повышенной детализацией;
- `sens_ask(question, region?)` — VQA через moondream;
- `sens_element(som_id)` — точные метрики элемента (бокс, шрифт, цвета, отступы);
- `sens_motion(url)` — документ моушена;
- legacy: `read/locate/inspect/compare` сохраняются;
- `sens_vision_prompt` — рекомендованный систем-сниппет для потребительской модели: «у тебя есть зрение через Sens; see даёт документ; детали запрашивай zoom/ask; на элементы ссылайся по номерам [id]».

## 7. Вайб и QA

Оценки не выносятся эвристиками. Вайб судит потребительская модель по документу (ascii + vibe-подпись + токены); для эстетических проверок — `sens_ask` («это выглядит намеренно или сломано?»). Геометрический QA потребитель делает по фактам из measurements. Это убирает ложные срабатывания на намеренных стилях.

## 8. Хостинг моделей и бюджет

Пик RAM ≈ 2.0 ГБ (moondream 1.7 + Florence int8 0.3). Только CPU. Латентность: Florence 0.5–2 с/кадр; moondream ~20–40 tok/s на CPU → первый `see` нового экрана 10–20 с; кэш по хэшу — мгновенно; `fast` — 2–4 с. Модели НЕ в git и НЕ в релизном бандле: `scripts/download-vision-models` (явный запуск пользователем); первый use без моделей — видимое уведомление, не тихая сеть. Резервный fast-tier, если moondream медленный на практике: SmolVLM2-500M Q8 (0.64 ГБ).

## 9. Ошибки и деградация

- vlm-worker не стартовал / моделей нет → документ без inferred-секций, `semantics_status=unavailable`, `see` работает на детерминированной части;
- таймаут VLM-вызова (конфиг, default 30 с) → секция пропускается с флагом, не ошибка;
- playwright отсутствует → `sens_capture`/`sens_motion(url)`/`see(url)` возвращают понятную ошибку с инструкцией;
- кэш: ключ = hash(image) + region + pipeline_schema_version; bump схемы инвалидирует;
- envelope: observed (OCR-тексты, DOM), measured (геометрия/цвета), inferred (VLM-подписи).

## 10. Тесты и приёмка

- Python unit-тесты: сборщик документа (дерево/SoM/токены/ascii), детекторы декоративного текста на синтетических фикстурах;
- приёмка на фикстурах (3 скриншота + 4 URL): круговой текст читается связно; dot-волна описана семантически («dot-matrix волна», не `texture`); vibe-дескрипторы попадают в стиль (brutalism/retro/dark-minimal); «MONO X7», не «MONIOXT»; `sens_motion` возвращает реальные анимации dope.security/caldera;
- e2e «воспроизведение»: документ → DeepSeek v4 Flash → HTML → рендер → `sens_compare` с оригиналом; порог калибруется на первом прогоне (стартовая цель — качественное «узнаваемо тот же дизайн» + количественный тренд снижения mismatch по итерациям);
- Rust: `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`.

## 11. Порядок сборки

1. Коммит незакоммиченной иерархии (+596 строк) + модульный рефакторинг sight-worker (entrypoint сохраняется);
2. vlm-worker + маршрутизация брокера + `scripts/download-vision-models`;
3. документ v1: токены + дерево + SoM + графика + ascii + measurements;
4. zoom/ask/element + `sens_vision_prompt`; MCP-инструменты;
5. url-capture + motion;
6. QA-рефрейм + legacy-поля под ключом `legacy`;
7. тесты + e2e на фикстурах + деплой в AppData\Local\Sens (воркер деплоится копией, не из D:\Sens).

## 12. Вне скоупа (YAGNI)

- GUI-действия (клики/скроллы как действия) — Sens воспринимает, а не агентит;
- понимание видео шире motion-событий;
- облачные VLM внутри пайплайна (Eye остаётся отдельной опциональной фичей);
- модели в репозитории/бандле.
